# 게임 데이터베이스 분석 포트폴리오
## 원신(Genshin Impact) & 트릭컬 리바이브

---

## 1. 과제 개요

### 1.1 과제 목적

게임에서 제공되는 다양한 기능과 데이터를 분석하고 이를 관계형 데이터베이스의 관점에서 구조화한다.

본 보고서에서는 **《원신(Genshin Impact)》**과 **《트릭컬 리바이브》**를 선정하여 다음과 같은 항목을 분석하였다.

- 게임의 주요 시스템 및 데이터 구조
- 데이터베이스에 필요한 개체(Entity)
- 각 개체의 속성(Attribute)
- 기본키(PK) 및 외래키(FK)
- 개체 간 관계(Relationship)
- 관계의 카디널리티(Cardinality)
- 관계형 데이터베이스 구조
- 과금 및 재화 시스템
- 게임별 ERD
- 두 게임의 데이터베이스 구조 비교

> **주의:** 게임사의 실제 운영 DB 구조와 테이블명은 공개되어 있지 않으므로, 본 보고서의 DB 구조는 게임의 실제 기능과 공개된 정보를 근거로 작성한 분석·추론 모델이다.

# 2. 게임 1 — 원신

## 2.1 게임 개요

《원신》은 HoYoverse에서 개발한 오픈월드 액션 RPG이다.

플레이어는 하나의 계정으로 게임에 접속하고, 여러 캐릭터를 획득하여 성장시키며 무기와 성유물을 장착하고 파티를 구성한다.

주요 데이터 시스템은 다음과 같이 분류할 수 있다.

1. 계정 및 플레이어
2. 캐릭터
3. 캐릭터 보유 정보
4. 캐릭터 성장
5. 무기
6. 무기 보유 및 강화
7. 성유물
8. 파티
9. 아이템 및 재화
10. 원석 및 기원
11. 기원 결과
12. 퀘스트
13. 업적
14. 결제 및 상품

---

## 2.2 원신의 주요 시스템 분석

### 2.2.1 계정 시스템

게임의 모든 플레이어 데이터는 계정과 연결된다.

| 속성 | 설명 |
|---|---|
| AccountID | 계정 식별자 |
| Nickname | 플레이어 닉네임 |
| UID | 게임 내 플레이어 식별번호 |
| AdventureRank | 모험 등급 |
| AdventureEXP | 모험 경험치 |
| WorldLevel | 월드 레벨 |
| CreatedAt | 계정 생성일 |
| LastLogin | 최근 접속 시간 |

**기본키:** `AccountID`

**후보키:** `UID`

UID 역시 플레이어를 구분할 수 있으므로 후보키로 사용할 수 있다.

| 속성 | 설명 |
|---|---|

# 3. 게임 2 — 트릭컬 리바이브

## 3.1 게임 개요

《트릭컬 리바이브》는 에피드게임즈에서 서비스하는 모바일 수집형 RPG이다.

게임에서는 플레이어가 다양한 사도 캐릭터를 획득하고 성장시키며, 사도 모집, 재화, 장비 및 상점 등의 시스템을 이용한다. 본 보고서의 트릭컬 ERD는 계정·사도 수집·성장·장비·재화·모집·상점·결제 시스템을 분석 범위로 하며, 기간 한정 이벤트 시스템은 범위에서 제외한다.

주요 분석 대상은 다음과 같다.

1. 교주 계정
2. 사도
3. 보유 사도
4. 사도 성장
5. 장비
6. 장비 장착
7. 재화
8. 인벤토리
9. 사도 모집
10. 모집 결과
11. 상점
12. 상품 구매
13. 결제

# 4. 두 게임의 데이터베이스 구조 비교

## 4.1 공통점

원신과 트릭컬은 장르와 게임 방식에 차이가 있지만 데이터베이스 관점에서는 공통적으로 다음 구조를 가진다고 분석할 수 있다.

### ① 계정과 캐릭터 데이터 분리

두 게임 모두 캐릭터의 기본 정보와 사용자가 실제로 보유한 캐릭터 정보를 분리하는 것이 적절하다.

```text
CHARACTER / APOSTLE
        ↓
OWNED_CHARACTER / OWNED_APOSTLE
        ↓
ACCOUNT / USER
```

캐릭터 기본 정보는 여러 사용자에게 공통으로 적용되지만, 레벨이나 성장 상태는 사용자마다 다르기 때문이다.

### ② 다대다 관계를 중간 테이블로 해결

원신에서는 한 계정이 여러 캐릭터를 보유하고, 하나의 캐릭터 종류는 여러 계정에서 보유할 수 있다.

```text
ACCOUNT 1 ─── N OWNED_CHARACTER N ─── 1 CHARACTER
```

트릭컬도 동일한 구조를 사용할 수 있다.

```text
USER 1 ─── N OWNED_APOSTLE N ─── 1 APOSTLE
```

### ③ 획득 기록 데이터가 중요

두 게임 모두 캐릭터를 획득하는 시스템이 있기 때문에 획득 이력을 저장하는 테이블이 필요하다.

원신:

```text
WISH_RECORD
```

트릭컬:

```text
RECRUITMENT_RECORD
```

이 데이터는 다음과 같은 운영 분석에 활용할 수 있다.

- 어떤 캐릭터가 언제 획득되었는가
- 어떤 모집/기원을 이용했는가
- 어떤 재화가 사용되었는가
- 이벤트별 획득량은 얼마인가

---

# 4.2 차이점

| 비교 항목 | 원신 | 트릭컬 리바이브 |
|---|---|---|
| 핵심 수집 대상 | 캐릭터 + 무기 + 성유물 | 사도 + 장비 |
| 핵심 획득 시스템 | 기원 | 사도 모집 |
| 장비 구조 | 무기 + 성유물 | 장비 중심 |
| 캐릭터 성장 | 레벨/돌파/별자리 등 | 레벨/성장/스킬 등 |
| 오픈월드 데이터 | 중요 | 상대적으로 중요도 낮음 |
| 파티 시스템 | 매우 중요 | 전투 편성 중심 |
| 이벤트 | 존재(이번 ERD에 미포함) | 분석 범위에서 제외 |
| 재화 시스템 | 원석/모라/재료 등 | 엘리프/티켓/이벤트 재화 등 |
| 과금 데이터 | 상품/결제/재화 | 상품/결제/재화 |
| 아이템 세분화 | 높음 | 높음 |
| 수집 기록 | 기원 기록 | 모집 기록 |

# 5. 데이터베이스 설계 관점에서의 차이

## 5.1 원신

원신은 오픈월드 RPG이기 때문에 캐릭터뿐만 아니라 다음과 같은 대규모 데이터를 추가적으로 관리해야 한다고 분석할 수 있다.

- 월드 데이터
- 지역
- NPC
- 퀘스트
- 몬스터
- 보물상자
- 채집물
- 순간이동 포인트
- 업적
- 탐험 진행도
- 낚시
- 하우징
- 이벤트

따라서 전체 DB 규모가 매우 커질 가능성이 있다.

특히 플레이어별 진행도를 저장해야 하는 시스템이 많기 때문에 계정 데이터를 중심으로 여러 하위 테이블이 연결되는 구조가 적절하다.

---

## 5.2 트릭컬 리바이브

트릭컬은 수집형 RPG의 특성상 다음 데이터가 상대적으로 중요하다.

- 사도
- 사도 성장
- 장비
- 재화
- 모집
- 모집 결과
- 상점
- 상품
- 결제

특히 사도 수집과 성장 시스템을 중심으로 DB가 구성될 가능성이 높다.

또한 기간 한정 이벤트가 반복적으로 운영되므로 이벤트별 데이터와 보상 데이터를 독립적인 테이블로 구성하는 것이 효율적이다.

---

# 6. 정규화 관점의 분석

본 설계에서는 데이터 중복을 줄이기 위해 기본적으로 정규화된 구조를 사용하였다.

예를 들어 캐릭터 정보를 다음처럼 저장하지 않는다.

```text
ACCOUNT
- UserID
- Character1Name
- Character1Level
- Character2Name
- Character2Level
- Character3Name
- Character3Level
```

이러한 구조는 캐릭터 수가 증가하면 컬럼이 계속 증가하고 관리가 어려워진다.

대신 다음과 같이 구성한다.

```text
ACCOUNT
      │
      └── OWNED_CHARACTER
                │
                └── CHARACTER
```

이렇게 하면 캐릭터가 추가되더라도 테이블의 구조를 변경하지 않고 새로운 행을 추가할 수 있다.

주요 기본키는 다음과 같이 설정할 수 있다.

| 테이블 | 기본키 |
|---|---|

| Character | CharacterID |
| OwnedCharacter | OwnedCharacterID |
| Weapon | WeaponID |
| OwnedWeapon | OwnedWeaponID |

| Item | ItemID |
| Inventory | InventoryID |
| Party | PartyID |
| WishBanner | BannerID |
| WishRecord | WishRecordID |
| Payment | PaymentID |

```text
OwnedCharacter.AccountID

OwnedCharacter.CharacterID

OwnedWeapon.AccountID

```

# 8. 결론

원신과 트릭컬 리바이브는 서로 다른 게임이지만, 데이터베이스 관점에서는 **계정 → 수집 대상 → 성장 → 아이템/재화 → 획득 기록 → 상점/과금**이라는 공통적인 구조를 발견할 수 있다.

원신은 오픈월드 RPG이므로 캐릭터, 무기, 성유물, 퀘스트, 탐험, 월드 등의 다양한 데이터가 서로 연결되는 대규모 구조가 필요하다고 분석할 수 있다.

반면 트릭컬 리바이브는 사도 수집과 성장, 모집, 재화 및 상점 시스템이 중요한 데이터 구조를 형성한다. 이벤트 시스템은 이번 트릭컬 ERD의 분석 범위에서 제외하였다.

특히 두 게임 모두 플레이어가 보유한 캐릭터와 게임에 존재하는 캐릭터의 기본 정보를 분리하는 것이 중요하다.

예를 들어 다음 구조를 사용하면 데이터 중복을 줄일 수 있다.

```text
CHARACTER
   │
   └──< OWNED_CHARACTER >── ACCOUNT
```

이를 통해 캐릭터의 기본 정보는 하나만 관리하고, 계정별 레벨·성장 상태 등의 데이터만 별도로 관리할 수 있다.

또한 기원/모집 시스템을 별도의 기록 테이블로 구성하면 사용자의 획득 기록을 저장할 수 있고, 상점 및 결제 시스템을 분리하면 상품 구매와 결제 내역을 구분하여 관리할 수 있다. 이벤트 시스템은 향후 확장 가능한 영역으로 남겨 두었다.

따라서 두 게임의 데이터베이스는 단순히 캐릭터 정보를 저장하는 형태가 아니라 **계정, 수집, 성장, 아이템, 재화, 확률형 획득, 이벤트, 상점, 결제 등의 여러 시스템을 관계형 구조로 연결하는 형태**로 설계하는 것이 적절하다.
