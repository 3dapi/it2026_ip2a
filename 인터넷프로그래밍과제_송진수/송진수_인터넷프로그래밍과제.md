# 게임 데이터베이스 분석 포트폴리오

## 1. 목적
기존 게임에서 사용되는 기능과 데이터를 분석하고, 이를 관계형 데이터베이스 관점에서 구조화한다. 게임 실행에서 확인할 수 있는 기능과 데이터를 근거로 데이터베이스 구조를 분석·추론하여 설계한다.

---

## 2. 장르별 아키텍처 설계 분석

### 2.1. 클래시 로얄
유저 성장 데이터와 실시간 매치 데이터를 분리하고, 덱 구성 요소의 빠른 조회를 처리하는 것이 핵심이다.

*   **도메인 모델링**
    *   **마스터 데이터:** arenaTBL - 아레나 해금 기준, cardTBL - 카드 고유 스펙
    *   **유저 상태 데이터:** userTBL - 재화 및 트로피, user_cardTBL - 보유 카드 인스턴스, deckTBL - 8장 덱 프리셋
    *   **소셜 및 매치 데이터:** clan_memberTBL - 클랜 소속 정보, match_historyTBL - 참여자별 성적 및 보상
*   **설계 주안점**
    *   **다대다 관계 해소:** 유저와 카드의 관계는 user_cardTBL 교차 테이블을 통해 두 개의 일대다 관계로 정규화하여 개별 카드의 획득량과 레벨을 추적한다.
    *   **조회 성능을 고려한 비정규화:** 인게임 진입 시 가장 빈번하게 조회되는 8장 덱 정보는 별도 교차 테이블을 두는 대신, deckTBL 내에 8개의 외래키 컬럼을 가로로 배치하는 비정규화를 적용해 단일 행 조회로 쿼리 오버헤드를 최소화한다.
    *   **무결성 제약조건:** 유저는 동시에 단 1개의 클랜에만 소속될 수 있으므로, clan_memberTBL의 기본키를 UserID로 설정해 중복 가입을 DB 레벨에서 원천 차단한다.

### 2.2. 전략적 팀 전투 (TFT)
매치 생성마다 방대한 임시 데이터가 발생하며, 특성 시너지와 아이템 조합이라는 복잡한 메타데이터 관계를 구조화하는 것이 중요하다.

*   **도메인 모델링**
    *   **마스터 데이터:** championTBL - 챔피언 스펙, traitTBL - 계열 및 직업, itemTBL - 조합법 및 스탯
    *   **매치 메타데이터:** matchTBL - 게임 진행 시간 및 버전, match_participantTBL - 8인 개별 결과 및 최종 등수
    *   **최종 보드 데이터:** match_unitTBL - 배치된 기물 및 장착 아이템
*   **설계 주안점**
    *   **자기 참조 구조:** 완성 아이템이 두 개의 하위 아이템으로 구성되는 로직은 itemTBL 내에 Recipe1_ItemID, Recipe2_ItemID 컬럼을 두어 자기 자신을 참조하게 만든다. 이를 통해 단일 테이블로 모든 티어의 아이템 조합 트리를 관리한다.
    *   **복합 외래키를 통한 강한 종속성 부여:** match_unitTBL은 특정 매치와 유저에게 강하게 종속된다. 부모 테이블인 match_participantTBL의 MatchID와 UserID 복합키를 상속받아 외래키로 설정하여 고아 레코드 발생을 방지한다.

### 2.3. 트릭컬 리바이브
마스터 데이터와 유저 획득 인스턴스 데이터 간 분리가 명확해야 하며, 복잡한 성장 재화 소모 트랜잭션 처리가 요구된다.

*   **도메인 모델링**
    *   **마스터 데이터:** characterTBL - 사도 태생 정보, equipmentTBL - 랭크업 장비
    *   **유저 상태 데이터:** userTBL - 계정 레벨 및 재화
    *   **사도 육성 인스턴스:** user_characterTBL - 사도 성장 상태, user_char_equipTBL - 장착 중인 장비, user_char_boardTBL - 크레파스 보드 개방 상태
    *   **덱 구성 데이터:** deck_slotTBL - 덱 프리셋 슬롯별 편성 정보
*   **설계 주안점**
    *   **비즈니스 룰의 DB 강제:** 덱 편성 테이블인 deck_slotTBL 설계 시 마스터 테이블을 직접 참조하지 않고, user_characterTBL의 UserID와 CharID를 복합 외래키로 참조한다. 이를 통해 해당 유저가 실제로 획득한 사도만 덱에 편성할 수 있다는 비즈니스 룰을 DB 제약조건으로 완벽히 보장한다.
    *   **상태 변경 트랜잭션 설계:** 사도가 6개 장비를 모두 모아 랭크업을 진행할 때, user_characterTBL의 랭크 값을 증가시킴과 동시에 user_char_equipTBL의 기존 장비 레코드를 일괄 삭제하는 로직이 단일 트랜잭션 내에서 원자성을 유지하도록 설계한다.

## 3. 결론
클래시 로얄, 전략적 팀 전투, 트릭컬 리바이브의 핵심 기능과 데이터를 바탕으로 데이터베이스 구조를 분석하고 설계했다. 실시간 대전 중심의 클래시 로얄은 빠른 덱 조회를 위한 비정규화와 다대다 관계 해소에 집중했다. 오토 배틀러인 전략적 팀 전투는 복잡한 아이템 조합을 위한 자기 참조 구조와 방대한 매치 데이터의 종속성을 보장하는 복합 외래키를 활용했다. 수집형 RPG인 트릭컬 리바이브는 마스터 데이터와 유저 데이터 간의 비즈니스 룰을 DB 제약조건으로 강제하고, 상태 변경 트랜잭션의 원자성을 유지하는 데 초점을 맞췄다. 결과적으로 각 게임의 코어 루프와 인게임 데이터 흐름을 분석하여, 데이터 참조 무결성과 조회 성능을 동시에 충족하는 관계형 데이터베이스 구조를 도출했다.
